## Back end (from class names - paths/hosts still to be extracted)
`com.channel5.userservice` is a Retrofit-based SDK with these API groups:
ActivationPin (TV sign-in code - relevant to Xbox), Consent, EmailValidation, Favourites / MyList,
MarketingConsent, MilkshakePinToExit, ParentalPin, Recommendations (+ reset), ResumePoints
(+ a "Corona" variant), SearchHistory, UserInfo, UserSession. Sessions are created with
`CreateCognitoSessionRequest` *(inference: AWS Cognito backed)*.

Catalogue models (`my5.logic.dataaccess.metadata.model`): Show, Watchable, Collection(+Corona/Edna/Hybrid
variants), Channel, ChannelTransmissions / NowNextItem (live schedule), ViewAllData, VodActionType.
Remote config (`ConfigDataClient`, `ConfigAWSDataClient`) supplies ad settings, player settings, policies,
system messages, upgrade settings, marketing-consent copy and analytics config.

## Update 2: endpoints, services and behaviours (strings + resources)
Method: DEX string table and decoded resources read with androguard (`scripts/dexstrings.py`,
`scripts/resstrings.py`); REA's decompiler returns nothing for abstract Retrofit interface methods,
so annotation paths come from string constants. Secrets/keys present in resources (analytics, push) are
deliberately **not** recorded here.

**Services**
- Config + playback service ("Cassie"): `config_base_url = https://cassie.channel5.com/`, platform id `my5androidng`,
  config path `config/app/...` *(inference: remote config is fetched from here at start-up, and it supplies the
  catalogue/user-service base URLs, which are therefore not hard-coded in the APK)*.
- Image host: `http://api-images.channel5.com/images/`. Episode web URL: `https://www.channel5.com/episode/`.
- Consent/CMP: `cdn.privacy.paramount.com` (OneTrust-style CMP). Help: `help.channel5.com`.
- Auth: AWS Cognito via the AWS Mobile Client (`CognitoService`: sign-in, sign-up, forgot-password).
- Content back ends named in code: "Corona" and "Edna" (collection/catalogue + resume points) alongside Cassie.

**User-service endpoints (verified from the Retrofit interfaces, decompiled with the JADX library)**
The annotations are obfuscated; letters map onto Retrofit's alphabet (b=DELETE f=GET n=PATCH o=POST p=PUT), which is consistent
across all interfaces (e.g. `favourites/{showId}` has GET, PUT and DELETE). Auth header is `Authorization: Bearer <token>`.
```
POST   activationPins                         -> {pin, pinSecret, qrCode}          # device-code sign-in step 1
GET    activationPins/{pin}/poll?longPoll=b   Bearer <pinSecret> -> {sessionToken, isRegistration}   # step 2 (poll)
PATCH  activationPins/{pin}                   Bearer <session>                       # the other device approves the pin
POST   user/validateCognitoToken                                                     # e-mail/password route (Cognito)

GET    /collections/mylist.json?platform=&milkshake=   -> {content[], contentType, totalItems}      # My List (host-absolute)
GET|PUT|DELETE favourites/{showId}   PUT body {platform, showId, showTitle}
POST   favourites/sync   (list of {showId, showTitle, platform, createdAt, updatedAt})   DELETE favourites

GET    /resumePoints?limit=250  -> {watchables:[{watchableId, resumeTimeInSeconds, durationInSeconds, platform, updatedAt}]}
GET|PUT /resumePoints/{watchableId}  PUT body {platform, resumeTimeInSeconds, durationInSeconds}
GET    /resumePoints/show/{showId}   PUT /resumePoints/sync   DELETE /resumePoints
GET|PUT|DELETE parentalPin    (server-side PIN; {pin, updatedAt})
anonymousUser/consent  anonymousUser/newUniqueId  emails/validateEmail
searchHistory/{showId}  settings/marketingConsent/{type}  recommendations/reset
geofence/request  geofence/report
```
Not yet known: how "pending" is signalled while polling a not-yet-approved pin (the app wraps the result in a Response and
inspects the status code), pin lifetime, the `updatedAt` unit (assumed epoch ms), and the catalogue/playback endpoints,
which are built from remote-config templates at run time.

Viewing analytics (Conviva-style "infinity"): `infinity/session/{start,beat,nav,stop}`,
`infinity/video/{init,start,pause,resume,seek,stop,joinTime,bufferUnderrun,error,ping,ad*}`.

**Playback and DRM (observed)**
- The player library validates `DRM_TYPE` in {STANDARD, PLAYREADY, WIDEVINE, CLEARKEY} with a licence URL
  (`DRM_URL`) per type, plus fallback DRM settings - so **PlayReady is a supported scheme**, which is what Xbox needs.
- Streaming: DASH (`.mpd`) and HLS (`.m3u8`); ads via VAST.
- Licence is requested per device through Cassie. Error copy shows the server enforces: UK location,
  VPN/proxy detection, per-device media-asset availability, and content rights.
- A television layout set (`layout-land-television`, `c5player.androidtv`) already exists, so the TV UX is
  documented by the app's own resources.

## Update 3: catalogue (search + show pages), config and data shapes
Source: decompiled config classes (JADX) plus a handful of read-only GETs made once, with the owner's go-ahead, to see the
response shapes. No real catalogue text is stored in this repo; the tests use invented data in the same shape.

**Config document** - `GET https://cassie.channel5.com/platform/{platform}/config.json?label={appVersion}` (no login,
`Access-Control-Allow-Origin: *`). Its `dataServiceSettings` carries the catalogue host and URL templates:
```
coronaBaseUri                         https://corona.channel5.com           ednaBaseUri  https://feeds-api.channel5.com
platformId                            (value the catalogue expects in ?platform=)
coronaShowQueryTemplateUri            /shows/search.json?platform={platformId}&genre={genre}&query={query}
coronaShowTemplateUri                 /shows/{showId}.json?platform={platformId}
coronaAllSeasonsByShowTemplateUri     /shows/{showId}/seasons.json?platform={platformId}
coronaAllEpisodesByShowTemplateUri    /shows/{showId}/episodes.json?platform={platformId}
coronaWatchableTemplateUri            /watchables/{watchableId}.json?platform={platformId}
coronaNowNextMetadataFeedTemplateUri  /channels/{channelId}/epg.json?start={startTime}&end={endTime}&platform={platformId}
ednaCollectionsTemplateUri            /collections/{collectionId}/concise.json?vod_available={platformId}
ednaImagesTemplateUri                 https://api-images.channel5.com/otis/images/{type}/{id}/{resolution}.{fmt}?overlay=...
```
The app fills `{name}` placeholders and strips any left unused. The catalogue answered from a non-UK network and with CORS `*`; playback is
the part that is region/VPN-checked.

**Response shapes** (field -> meaning)
* search: `{size, shows:[{id, title, genre, child_directed, primary_vod_genre, vod_subgenres[], chan, s_desc, img_upd, use_title_img}]}`
* show: the same fields plus `won_id`, `chan_name`, `m_desc` (long description)
* seasons: `{seasons:[{seasonNumber:"1", numberOfEpisodes, seasonUseTitleImg}]}`
* episodes: `{size, episodes:[{id, title, sh_id, sh_title, sea_num:"1", ep_num, s_desc, adv, genre, child_directed, rat, len(ms), vod_s/vod_e(epoch s = availability window), vod_ad, vod_sub, chan, tags[], img_upd, credits_duration_in_seconds}]}`
* `rat` values seen: only `G` and `G+` (meaning not documented). Search results carry no rating.

Implemented in `web/js/live.js` (read-only: search, show, episodes). Not implemented: home rails/collections, images, TV guide, anything with an account, playback.

## Decisions needed before building the client
- The official app's Cognito client id, API keys and Cassie platform id identify *the official app*. A third-party
  Xbox client reusing them would be impersonating it and may be blocked or breach Channel 5's terms. Prefer asking
  Channel 5 for partner access, or limit the project to personal use with the user's own account.
- UK-only and VPN checks are enforced server-side; this project will not try to defeat them.
